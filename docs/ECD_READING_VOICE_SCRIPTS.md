# 3 · Shared feedback

These play in every reading game, so record them once.

## The two cues

These are sounds, not speech — no script, nothing to read. They play *first*,
and the spoken line below follows only once the cue has finished.

**`phonics/feedback/success.mp3`** — the fanfare on a correct answer.

**`phonics/feedback/wrong.mp3`** — the gentle note on a wrong one. Keep it soft
and unbothered: it marks a miss, it does not tell anyone off.

## When the child gets it right

One of the five is chosen at random — hearing the same cheer every time gets
old fast. It plays after `success.mp3` has finished.

**`phonics/feedback/correct-1.mp3`**

> [claps and laughs] Yes! You did it! That's the one!

**`phonics/feedback/correct-2.mp3`**

> [cheers] Woo-hoo! You are a super sound finder!

**`phonics/feedback/correct-3.mp3`**

> [giggles] Brilliant! Your listening ears are working perfectly!

**`phonics/feedback/correct-4.mp3`**

> [happy gasp] Wow! That is exactly right! High five!

**`phonics/feedback/correct-5.mp3`**

> [laughs] Yes, yes, yes! You are getting so good at this!

## When the child picks wrong

Warm and playful, never disappointed. The child should want to try again. It
plays after `wrong.mp3` has finished.

**`phonics/feedback/tryagain-1.mp3`**

> [gentle giggle] Ooh, not that one. Have a listen again — you can do it!

**`phonics/feedback/tryagain-2.mp3`**

> [warmly] So close! Let's use our listening ears one more time.

**`phonics/feedback/tryagain-3.mp3`**

> [playful hmm] Hmm, that one sounds different. Try again!

**`phonics/feedback/tryagain-4.mp3`**

> [encouraging] Nearly there, my friend. Have another go!

**`phonics/feedback/tryagain-5.mp3`**

> [soft chuckle] Oops! No problem at all. Let's try once more!

## When a game is finished

**`phonics/feedback/finished.mp3`**

> [cheers and claps] Hooray! You finished them all! [giggles] You are a reading star. Shall we play again?

# 4 · Number Drive (maths)

## The counting voice — one recording, not twenty

All twenty numbers go into **one file**:

```
public/sounds/ecd/maths/numbers.mp3
```

The game plays a single number by seeking to its slice of that file. One take
is far easier to record — and to re-record in the same voice on a different
day — than twenty separate clips.

### How to record it

Read the script below straight through in one take. The only thing that
matters technically is the **silence between numbers**:

| | |
|---|---|
| **Pause between numbers** | A full **one second** of real silence. Count "and-a-one" in your head |
| **Do not** | Breathe, swallow, tap, or say "um" in the gap — any sound there splits the slice in the wrong place |
| **Room** | As quiet as you can get. Background hum is what makes the gaps undetectable |
| **Delivery** | Bright and clear, the way you would count with a child. Slightly slower than normal speech |
| **Format** | MP3, 128 kbps mono, normalised to about −6 dB peak |

Say **only** the number. No "number three", no "that's three" — just the word.

### The script

> One.
>
> Two.
>
> Three.
>
> Four.
>
> Five.
>
> Six.
>
> Seven.
>
> Eight.
>
> Nine.
>
> Ten.
>
> Eleven.
>
> Twelve.
>
> Thirteen.
>
> Fourteen.
>
> Fifteen.
>
> Sixteen.
>
> Seventeen.
>
> Eighteen.
>
> Nineteen.
>
> Twenty.

Each blank line is your one-second pause.

### After recording

Run this once, and the game starts using the recording:

```bash
npm run numbers:map
```

It asks ffmpeg where the file is actually silent, works out where each number
starts and ends, and writes those positions to `src/data/ecdNumberVoice.json`. It
prints the twenty slices it found — check the count is **20**. If it is not, a
pause was too short to detect, or something made a noise in a gap; re-record
the numbers that ran together and run it again.

Until that command has been run, the game reads the numbers with the browser's
own voice, so it is playable either way.

## The car

Three sounds, all under `public/sounds/ecd/car/`:

**`car-starting.mp3`** — the ignition. Plays once as the game opens; the engine
loop takes over the moment it finishes.

**`car-moving.mp3`** — the engine running. This one **loops**, so the end must
join back onto the start with no click or gap. Steady engine, no revs or gear
changes that would repeat conspicuously. Keep it soft — it runs under
everything else for as long as the child is driving.

**`car-crash.wav`** — the bump when the car drives into the wrong number. This
is the *only* thing a wrong answer plays: no buzzer, no spoken telling-off. A
soft comic thud under a second. It is a miss in a counting game, not a road
accident — nothing alarming, nothing metallic.

## Checking your work

Run the site and open `/ecd/reading/phonics` or `/ecd/reading/rhyming`, then
step through using the strip along the bottom. Anything still read by the robot
voice has no file yet, or the file name does not match. Names are lower-case and
the extension is `.mp3`.

The scripts live beside the code — `src/features/ecd/reading/phonicsAlphabet.ts`
and `src/features/ecd/reading/rhymingWords.ts`, with the shared feedback in
`readingVoice.ts`. Edit them there and this sheet can be regenerated from the
same wording, so the two can never disagree.
